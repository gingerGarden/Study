# 3. Tool Calling 설계

Tool Calling은 LLM이 외부 기능을 사용할 수 있게 하는 구조입니다. Multi-turn Agent에서 도구는 검색, DB 조회, 계산, 파일 처리, 보고서 생성, 알림 전송 같은 실제 작업을 담당합니다.

중요한 점은 LLM이 도구를 직접 실행하는 것이 아니라, 도구 호출 요청을 생성하고 애플리케이션이 검증 후 실행한다는 것입니다.

## 3.1. 도구 정의

도구는 이름, 설명, 입력 스키마, 출력 스키마, 실패 가능성을 함께 정의해야 합니다.

```json
{
  "name": "search_papers",
  "description": "논문 데이터베이스에서 조건에 맞는 논문을 검색한다.",
  "input_schema": {
    "query": "string",
    "start_year": "integer",
    "end_year": "integer",
    "limit": "integer"
  },
  "output_schema": {
    "papers": "array",
    "total_count": "integer"
  },
  "side_effect": false
}
```

도구 설명은 LLM이 언제 도구를 써야 하는지 판단하는 근거가 됩니다. 이름과 설명이 모호하면 잘못된 도구 선택이 늘어납니다.

## 3.2. 도구 분류

| 유형 | 예시 | 주의점 |
| --- | --- | --- |
| Read-only | 검색, 조회, 계산 | 반복 호출 비용 관리 |
| Write | DB 저장, 파일 생성 | 승인, 권한, 롤백 필요 |
| External API | 결제, 메일, Slack | 실패, rate limit, 중복 실행 방지 |
| Long-running | 대량 분석, 보고서 생성 | 비동기 Job으로 관리 |
| Sensitive | 개인정보 조회, 권한 변경 | 정책 검증과 감사 로그 필수 |

도구에 부작용이 있을수록 LLM에게 직접 맡기는 범위를 줄여야 합니다.

## 3.3. 입력값 검증

LLM이 생성한 인자는 항상 검증해야 합니다.

```python
from pydantic import BaseModel, Field, model_validator


class SearchPapersInput(BaseModel):
    query: str = Field(min_length=1)
    start_year: int = Field(ge=1900)
    end_year: int = Field(ge=1900)
    limit: int = Field(default=100, ge=1, le=1000)

    @model_validator(mode="after")
    def validate_range(self) -> "SearchPapersInput":
        if self.start_year > self.end_year:
            raise ValueError("start_year는 end_year보다 클 수 없습니다.")
        return self
```

검증 실패 시에는 바로 도구를 실행하지 말고, LLM에 오류를 관찰값으로 전달하거나 사용자에게 확인 질문을 해야 합니다.

## 3.4. 도구 실행 결과

도구 결과는 원본과 요약을 구분해 저장하는 것이 좋습니다.

```json
{
  "tool_call_id": "call_001",
  "tool": "search_papers",
  "status": "success",
  "summary": "검색 결과 100건 반환",
  "result_ref": "artifact_papers_001"
}
```

프롬프트에는 전체 원본을 넣기보다 필요한 요약과 참조 ID만 넣어야 토큰 비용을 줄일 수 있습니다.

## 3.5. 실패 처리

도구 실패는 종류별로 다르게 처리해야 합니다.

| 실패 유형 | 처리 방식 |
| --- | --- |
| 입력값 오류 | 사용자에게 확인 질문 |
| 일시적 네트워크 오류 | 제한된 횟수만 재시도 |
| 권한 오류 | 실행 중단 및 권한 안내 |
| 결과 없음 | 검색 조건 완화 제안 |
| 도구 내부 오류 | 로그 저장 후 복구 가능한 대안 제시 |

모든 도구에 공통으로 적용할 제한값을 두어야 합니다.

```python
MAX_TOOL_RETRIES = 2
MAX_TOOL_CALLS_PER_TURN = 5
TOOL_TIMEOUT_SECONDS = 30
```

## 3.6. 중복 실행 방지

메일 발송, 결제, DB 변경처럼 부작용이 있는 도구는 idempotency key를 사용해야 합니다.

```json
{
  "tool": "send_email",
  "idempotency_key": "session_1_turn_5_send_email_report"
}
```

같은 요청이 재시도되더라도 동일 작업이 두 번 실행되지 않게 해야 합니다.
