# 8. Plan-and-Execute 방식
먼저 전체 작업 계획을 만들고, 계획된 단계를 순서대로 실행하는 방식입니다.

```
사용자 요청
    ↓
Planner가 실행 계획 생성
    ↓
Executor가 각 단계 실행
    ↓
결과 검증
    ↓
필요하면 계획 수정
    ↓
최종 응답
```

예시는 다음과 같습니다.

```json
{
  "goal": "기능성 원료 관련 논문 검색 및 분석",
  "steps": [
    {
      "step": 1,
      "action": "검색어 생성"
    },
    {
      "step": 2,
      "action": "논문 검색"
    },
    {
      "step": 3,
      "action": "중복 제거"
    },
    {
      "step": 4,
      "action": "주제 분류"
    },
    {
      "step": 5,
      "action": "결과 요약"
    }
  ]
}
```

### 장점
* 복잡한 작업의 전체 흐름을 관리하기 쉬움
* 진행 상황을 사용자에게 설명하기 좋음
* 단계별 실패와 재시도 처리가 가능함
* 장시간 수행되는 업무에 적합함

### 단점
* 처음 생성한 계획이 잘못될 수 있음
* 간단한 요청에도 불필요한 계획을 만들 수 있음
* 실행 중 상황이 바뀌면 재계획이 필요함

연구 분석, 보고서 작성, 여러 API를 연계하는 업무에 적합합니다.

Planner와 Executor의 역할은 분리하는 것이 좋습니다.

| 역할 | 책임 |
| --- | --- |
| Planner | 목표를 단계로 분해하고 실행 순서를 정함 |
| Executor | 각 단계를 실제 도구 호출이나 코드 실행으로 수행함 |
| Validator | 단계 결과가 요구사항을 만족하는지 확인함 |
| Replanner | 실패나 조건 변경이 있을 때 계획을 수정함 |

계획은 사람이 읽을 수 있는 설명만이 아니라 실행 가능한 구조를 가져야 합니다.

```json
{
  "step_id": "search_papers",
  "description": "기능성 원료 관련 논문을 검색한다.",
  "tool": "search_papers",
  "inputs": {
    "query": "기능성 원료",
    "start_year": 2021,
    "end_year": 2026
  },
  "success_condition": "검색 결과가 1건 이상 존재한다."
}
```

### 구현 시 주의점
* 계획 단계가 너무 추상적이면 Executor가 안정적으로 실행하기 어려움
* 계획 단계가 너무 세밀하면 간단한 작업에도 오버헤드가 커짐
* 사용자 요구가 바뀌면 기존 계획을 폐기할지 부분 수정할지 판단해야 함
* 각 단계의 성공 조건을 명시해야 재시도와 중단 판단이 가능함

Plan-and-Execute 방식은 ReAct보다 전체 흐름을 설명하기 쉽고, ReAct는 실행 중 관찰에 따라 유연하게 움직이기 쉽습니다. 실제 구현에서는 계획 기반으로 큰 단계를 잡고, 각 단계 내부를 ReAct처럼 처리하는 혼합 방식도 자주 사용됩니다.
