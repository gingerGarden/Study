# 5. 슬롯 기반 방식
사용자 요청에 필요한 값을 미리 정의하고, 대화를 통해 빈 슬롯을 채우는 방식입니다.

```json
{
  "topic": null,
  "start_year": null,
  "end_year": null,
  "result_limit": null,
  "output_format": null
}
```

대화는 다음처럼 진행됩니다.

```
사용자: 논문을 검색해줘.
Agent: 검색 주제를 입력해 주세요.

사용자: 기능성 원료.
Agent: 검색 기간을 입력해 주세요.

사용자: 최근 5년.
Agent: 결과는 몇 건까지 조회할까요?
```

### 장점
* 동작을 예측하기 쉬움
* 필수 정보 누락을 방지할 수 있음
* 신청서, 예약, 검색 조건 설정에 적합함
* 검증 규칙을 적용하기 쉬움

### 단점
* 정해진 시나리오 외 요청에 유연하지 못함
* 지나치게 기계적인 대화가 될 수 있음
* 복잡한 자연어 업무에는 한계가 있음

기존 챗봇의 Dialog State Tracking과 유사하며, LLM과 결합하면 자연어 이해 능력을 보완할 수 있습니다.

슬롯은 단순히 값을 채우는 데서 끝나지 않고, 각 슬롯의 검증 규칙과 질문 문구를 함께 정의하는 것이 좋습니다.

```json
{
  "topic": {
    "required": true,
    "value": null,
    "question": "검색할 주제를 입력해 주세요."
  },
  "start_year": {
    "required": true,
    "value": null,
    "validation": "1900 이상 현재 연도 이하"
  },
  "result_limit": {
    "required": false,
    "value": 100,
    "validation": "1 이상 1000 이하"
  }
}
```

### 슬롯 채우기 흐름

```
사용자 입력
    ↓
슬롯 후보 추출
    ↓
값 검증
    ↓
누락 슬롯 확인
    ↓
다음 질문 또는 작업 실행
```

### 구현 시 주의점
* 사용자가 한 문장에 여러 슬롯을 한꺼번에 제공할 수 있어야 함
* 기본값이 있는 슬롯과 반드시 물어봐야 하는 슬롯을 구분해야 함
* 사용자가 이전 값을 수정할 수 있어야 함
* 모든 슬롯이 채워진 뒤에도 실행 전 확인 단계가 필요할 수 있음

슬롯 기반 방식은 구조화된 State 방식의 특수한 형태로 볼 수 있습니다. 필수 입력값이 명확한 업무에서는 먼저 슬롯 기반으로 구현하고, 이후 복잡도가 커지면 일반 State 모델로 확장하는 접근이 현실적입니다.
