# 2. 대화 요약본 방식
오래된 대화를 요약하여 하나의 압축된 문맥으로 유지하고, 최근 대화는 원문으로 보존하는 방식입니다.

```
전체 대화
    ↓
오래된 대화와 최근 대화 분리
    ↓
오래된 대화 요약
    ↓
요약본 + 최근 N턴 + 현재 요청
    ↓
LLM 호출
```

LLM에 전달되는 프롬프트는 다음과 같습니다

```
[기존 대화 요약]

사용자는 기능성 원료 논문 검색 Agent를 개발하고 있다.
검색 범위는 최근 5년이며, 논문의 제목·초록·키워드를 활용한다.
검색 결과는 관련도순으로 정렬하고 상위 100건을 반환하기로 했다.

[최근 대화]

사용자: 검색 결과를 주제별로 분류하고 싶어.
Agent: 임베딩 클러스터링이나 LLM 분류를 사용할 수 있습니다.

사용자: LLM 분류 방식으로 해줘.

[현재 요청]

분류 결과의 출력 스키마를 작성해줘.
```

### 장점
* 긴 대화의 전체 흐름을 비교적 적은 토큰으로 유지함
* 단일 세션이 오래 지속되는 업무에 적합함
* 최근 대화와 장기 문맥을 함께 활용할 수 있음

### 단점
* 요약 과정에서 정보가 누락될 수 있음
* 잘못 생성된 요약이 이후 대화에 계속 영향을 미침
* 반복 요약으로 수치나 세부 조건이 변형될 수 있음
* 요약을 위한 추가 LLM 호출이 필요함

따라서 요약에는 다음 내용을 명시적으로 유지해야 합니다.

```
- 사용자의 최종 목표
- 확정된 요구사항
- 중요한 수치와 고유명사
- 사용자가 선택한 방안
- 사용자가 거부한 방안
- 미완료 작업
- 최근 변경사항
```

요약은 자유문 형태보다 일정한 구조를 갖는 편이 안정적입니다.

```markdown
## Goal
기능성 원료 관련 논문 검색 및 주제 분류 Agent를 구현한다.

## Decisions
- 검색 기간은 2021년부터 2026년까지로 한다.
- 결과는 관련도순 상위 100건을 반환한다.
- 분류 방식은 LLM 분류를 사용한다.

## Rejected Options
- 임베딩 클러스터링 방식은 우선 사용하지 않는다.

## Open Items
- 출력 스키마를 정의해야 한다.
- 검색 API 입력값 검증이 필요하다.
```

요약 갱신은 매 턴마다 수행할 수도 있지만, 비용을 줄이려면 다음 조건에서만 수행할 수 있습니다.

* 누적 메시지가 일정 토큰 수를 초과함
* 사용자가 중요한 결정을 변경함
* 도구 실행 결과가 작업 상태에 영향을 줌
* 세션 종료 전에 이어하기용 상태를 저장해야 함

요약본은 항상 최신 사용자 지시보다 낮은 우선순위를 가져야 합니다. 오래된 요약과 현재 요청이 충돌하면 현재 요청을 반영하고 요약을 갱신해야 합니다.
