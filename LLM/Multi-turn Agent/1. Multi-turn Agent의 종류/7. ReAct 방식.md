# 7. ReAct 방식
ReAct는 LLM이 현재 상황을 판단하고, 필요한 도구를 호출한 뒤, 결과를 다시 관찰하여 다음 행동을 결정하는 방식입니다.

개념적인 흐름은 다음과 같습니다.

```
사용자 요청
    ↓
행동 결정
    ↓
도구 호출
    ↓
도구 실행 결과 관찰
    ↓
추가 행동 필요 여부 판단
    ↓
최종 응답
```

예를 들어 다음과 같은 실행 흐름이 가능합니다.

```
사용자:
최근 5년간 기능성 원료 관련 논문을 검색해서 주제별로 분류해줘.

Agent 행동:
1. 논문 검색 도구 호출
2. 검색 결과 확인
3. 중복 논문 제거 도구 호출
4. 논문 분류 도구 호출
5. 분류 결과 검증
6. 최종 결과 응답
```

### 장점
* 복잡한 작업을 여러 단계로 처리할 수 있음
* 도구 실행 결과에 따라 다음 행동을 바꿀 수 있음
* 검색, 분석, 계산, 문서 생성 등을 연결할 수 있음

### 단점
* 불필요하게 도구를 반복 호출할 수 있음
* 종료 조건이 불명확하면 루프가 길어질 수 있음
* LLM의 잘못된 도구 선택을 통제해야 함
* 비용과 지연시간이 증가할 수 있음

실제 구현에서는 최대 반복 횟수, 사용 가능한 도구, 종료 조건을 명시적으로 제한해야 합니다.

구현 흐름은 다음처럼 구성할 수 있습니다.

```python
for iteration in range(MAX_AGENT_ITERATIONS):
    action = llm_decide_next_action(context)

    if action.type == "final_answer":
        return action.content

    if action.tool_name not in allowed_tools:
        raise ValueError("허용되지 않은 도구입니다.")

    tool_result = run_tool(action.tool_name, action.arguments)
    context.add_observation(tool_result)

raise TimeoutError("최대 반복 횟수에 도달했습니다.")
```

ReAct 방식에서 중요한 것은 LLM의 사고 과정을 그대로 노출하는 것이 아니라, 관찰 가능한 행동과 결과를 반복적으로 관리하는 것입니다.

### 설계 시 제한해야 하는 요소
* Agent가 사용할 수 있는 도구 목록
* 각 도구의 입력 스키마
* 최대 반복 횟수
* 같은 도구의 연속 호출 횟수
* 최종 응답을 생성해야 하는 조건
* 도구 실패 시 재시도 횟수

ReAct는 자유도가 높은 만큼, 도구 실행 비용이 크거나 부작용이 있는 업무에서는 승인 단계나 정책 검증을 추가해야 합니다.
