# 5. 구현 프레임워크

Multi-turn Agent는 직접 구현할 수도 있고, Agent 프레임워크를 사용할 수도 있습니다. 프레임워크를 선택할 때는 기능 수보다 상태 관리, 도구 호출, 관찰 가능성, 운영 통제 가능성을 봐야 합니다.

## 5.1. 직접 구현

직접 구현은 가장 단순한 구조에서 시작하기 좋습니다.

```python
def handle_turn(user_input: str, session_id: str) -> str:
    history = load_recent_messages(session_id)
    state = load_state(session_id)
    memories = search_memories(user_input)

    prompt = build_prompt(history, state, memories, user_input)
    response = call_llm(prompt)

    if response.tool_call:
        result = execute_tool(response.tool_call)
        save_tool_result(session_id, result)
        return handle_turn_with_observation(session_id, result)

    save_message(session_id, "assistant", response.content)
    return response.content
```

직접 구현은 내부 동작을 명확하게 통제할 수 있지만, 그래프 실행, 재시도, 체크포인트, 관찰성 기능을 직접 만들어야 합니다.

## 5.2. LangGraph

LangGraph는 Agent를 그래프와 상태 전이 중심으로 구현할 때 적합합니다.

적합한 경우:

* 명시적인 State가 있음
* Workflow나 State Machine이 필요함
* 중간 상태 저장과 재시작이 중요함
* 여러 노드가 순차 또는 조건부로 실행됨

개념 구조는 다음과 같습니다.

```python
class AgentState(TypedDict):
    messages: list
    task: dict
    next_step: str


def planner_node(state: AgentState) -> AgentState:
    ...


def tool_node(state: AgentState) -> AgentState:
    ...


def validator_node(state: AgentState) -> AgentState:
    ...
```

LangGraph는 복잡한 Multi-turn Workflow Agent에 적합하지만, 단순 챗봇에는 오버헤드가 있을 수 있습니다.

## 5.3. LangChain

LangChain은 LLM, Prompt, Tool, Retriever를 빠르게 연결하는 데 유용합니다.

적합한 경우:

* RAG나 Tool Calling을 빠르게 구성해야 함
* 다양한 LLM Provider를 바꿔가며 실험해야 함
* 문서 로더, Retriever, Tool 통합이 필요함

다만 복잡한 상태 전이와 운영 통제는 별도 설계가 필요할 수 있습니다.

## 5.4. AutoGen 계열

AutoGen 계열은 여러 Agent 역할을 나누어 협업시키는 실험에 적합합니다.

적합한 경우:

* Planner, Coder, Reviewer처럼 역할을 분리함
* 여러 Agent가 토론하거나 검토해야 함
* 복잡한 분석 작업을 분업하고 싶음

다만 멀티 에이전트 구조는 비용과 제어 복잡도가 커지므로, 단일 Agent로 충분한 문제인지 먼저 판단해야 합니다.

## 5.5. 선택 기준

| 상황 | 추천 |
| --- | --- |
| 학습 목적 | 직접 구현 |
| 간단한 서비스 | 직접 구현 + 필요한 라이브러리 |
| 상태 전이가 복잡함 | LangGraph |
| RAG와 Tool 연결 중심 | LangChain |
| 역할 분담 실험 | AutoGen 계열 |
| 기업용 운영 | 직접 통제 가능한 구조 + 검증 계층 |

프레임워크는 Agent의 핵심 설계를 대신해 주지 않습니다. History, State, Memory, Tool, Validation의 책임 분리는 어떤 프레임워크를 쓰더라도 직접 설계해야 합니다.
