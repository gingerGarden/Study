# 9. 전문가 학습 로드맵

이 문서 세트를 모두 읽으면 Multi-turn Agent의 기본 개념과 실무 설계 요소를 넓게 이해할 수 있습니다. 하지만 전문가가 되려면 개념 이해를 넘어 직접 구현, 평가, 운영까지 경험해야 합니다.

## 9.1. 학습 순서

추천 순서는 다음과 같습니다.

```
1. Multi-turn Agent 개념 이해
2. 종류별 구현 방식 비교
3. History, State, Memory 분리 구현
4. Tool Calling과 검증 구현
5. Workflow 또는 ReAct 루프 구현
6. 평가 시나리오 작성
7. 보안과 권한 정책 추가
8. 운영 로그와 모니터링 구성
9. 실제 서비스 시나리오에 적용
```

## 9.2. 직접 만들어 볼 예제

전문성을 키우려면 다음 예제를 순서대로 구현하는 것이 좋습니다.

| 단계 | 예제 | 핵심 학습 |
| --- | --- | --- |
| 1 | 최근 N턴 챗봇 | 대화 이력 관리 |
| 2 | 논문 검색 조건 수집 Agent | 슬롯과 State |
| 3 | 긴 상담 요약 Agent | 요약본 갱신 |
| 4 | 논문 검색 Tool Agent | Tool Calling |
| 5 | 보고서 생성 Workflow Agent | Plan, Execute, Validate |
| 6 | 사용자 선호 기억 Agent | Semantic Memory |
| 7 | 보안 정책이 있는 Agent | 권한, 승인, 감사 로그 |
| 8 | 운영 가능한 Agent API | 로그, 비용, 장애 대응 |

이 문서 세트에서는 `10. 실전 구현 예제` 디렉터리에 논문 검색 Agent 예제를 제공한다. 이 예제는 State, Tool Calling, Memory, 실패 처리, 테스트 시나리오가 하나의 흐름에서 어떻게 연결되는지 보여준다.

## 9.3. 전문가 기준 체크리스트

다음 질문에 답할 수 있으면 실무 전문가에 가까워집니다.

* 대화 이력, State, Memory를 왜 분리해야 하는가
* 최신 사용자 지시와 과거 Memory가 충돌하면 어떻게 처리하는가
* Tool Calling 입력값은 어디서 검증해야 하는가
* 부작용이 있는 도구는 어떻게 보호해야 하는가
* ReAct 루프가 멈추지 않는 문제를 어떻게 방지하는가
* Plan-and-Execute에서 계획 실패를 어떻게 복구하는가
* Multi-turn Agent를 어떻게 테스트하고 회귀 검증하는가
* prompt injection을 어떻게 방어하는가
* 비용이 급증할 때 어떤 지표를 먼저 봐야 하는가
* 장기 Memory를 사용자가 삭제할 수 있게 하려면 어떤 구조가 필요한가

## 9.4. 이 문서 세트의 위치

현재 문서 세트는 다음 수준을 목표로 합니다.

| 수준 | 설명 | 이 문서 세트의 커버리지 |
| --- | --- | --- |
| 입문 | 개념과 용어 이해 | 충분함 |
| 초급 실무 | 간단한 Multi-turn Agent 구현 | 충분함 |
| 중급 실무 | State, Tool, Memory 조합 설계 | 대부분 포함 |
| 고급 실무 | 보안, 평가, 운영까지 고려 | 핵심 기준 포함 |
| 전문가 | 실제 서비스 운영 경험과 장애 대응 | 문서만으로는 부족 |

따라서 이 문서만 읽는다고 전문가가 되는 것은 아니지만, 전문가가 되기 위해 어떤 구조를 공부하고 구현해야 하는지는 판단할 수 있습니다.
