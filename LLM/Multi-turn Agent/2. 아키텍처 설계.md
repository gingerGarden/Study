# 2. 아키텍처 설계

Multi-turn Agent는 LLM 호출 코드 하나가 아니라, 대화 문맥, 작업 상태, 도구 실행, 검증, 저장소를 조합한 애플리케이션 구조입니다.

가장 기본적인 아키텍처는 다음과 같이 나눌 수 있습니다.

```
Client
  ↓
API Server
  ↓
Agent Controller
  ├─ Conversation Store
  ├─ Agent State Store
  ├─ Memory Retriever
  ├─ Prompt Builder
  ├─ LLM Client
  ├─ Tool Executor
  └─ Validator
```

## 2.1. 핵심 컴포넌트

| 컴포넌트 | 역할 |
| --- | --- |
| Agent Controller | 한 턴의 전체 실행 흐름을 조정 |
| Conversation Store | 사용자와 Agent의 메시지 저장 |
| State Store | 현재 작업 상태와 확정 조건 저장 |
| Memory Store | 세션을 넘어 유지할 정보 저장 |
| Prompt Builder | 현재 요청에 필요한 문맥 구성 |
| LLM Client | 모델 호출 및 응답 파싱 |
| Tool Executor | 외부 API, DB, 파일, 검색 도구 실행 |
| Validator | 입력값, 도구 결과, 최종 응답 검증 |

Agent Controller는 모든 판단을 LLM에 맡기지 않고, 애플리케이션 레벨에서 실행 순서와 안전장치를 관리해야 합니다.

## 2.2. 한 턴의 처리 흐름

```
1. 사용자 입력 수신
2. 최근 대화 조회
3. Agent State 조회
4. 관련 Memory 검색
5. Prompt 구성
6. LLM 호출
7. 응답이 도구 호출인지 최종 답변인지 판단
8. 도구 호출이면 입력값 검증 후 실행
9. 도구 결과를 관찰값으로 추가
10. 필요하면 반복
11. State, History, Memory 갱신
12. 사용자에게 응답 반환
```

실무에서는 각 단계가 실패할 수 있으므로, 실패 지점을 구분해 로그를 남겨야 합니다.

```json
{
  "turn_id": "turn_20260729_001",
  "user_id": "user_1",
  "session_id": "session_1",
  "current_step": "tool_execution",
  "status": "failed",
  "error_code": "TOOL_TIMEOUT",
  "retryable": true
}
```

## 2.3. 상태 저장소 분리

Conversation, State, Memory는 목적이 다르므로 분리하는 것이 좋습니다.

| 저장소 | 저장 대상 | 예시 |
| --- | --- | --- |
| Conversation | 실제 메시지 | user, assistant, tool 메시지 |
| State | 현재 작업의 구조화된 값 | 검색 조건, 진행 단계 |
| Memory | 장기적으로 재사용할 정보 | 사용자 선호, 프로젝트 결정사항 |
| Artifact | 생성된 결과물 | 보고서, 파일, 검색 결과 원본 |

모든 정보를 하나의 대화 기록에만 넣으면 긴 세션에서 비용이 커지고, 중요한 결정사항을 안정적으로 추적하기 어렵습니다.

## 2.4. 동기 처리와 비동기 처리

짧은 답변은 동기 처리로 충분하지만, 검색, 분석, 보고서 생성처럼 오래 걸리는 작업은 비동기 구조가 필요합니다.

| 처리 방식 | 적합한 작업 |
| --- | --- |
| 동기 요청-응답 | 짧은 질의응답, 간단한 도구 호출 |
| 비동기 Job | 대량 검색, 파일 분석, 보고서 생성 |
| Streaming | 긴 답변 생성, 진행 상황 표시 |
| Human-in-the-loop | 승인, 결제, 삭제, 배포 |

비동기 작업은 `job_id`, `status`, `progress`, `result_ref`를 명시적으로 관리해야 합니다.

## 2.5. 설계 원칙

* LLM은 판단 후보를 만들고, 애플리케이션은 실행을 통제함
* 대화 이력과 작업 상태를 분리함
* 도구 입력과 출력은 스키마로 검증함
* 장기 작업은 중단, 재시작, 재시도가 가능해야 함
* 사용자에게 보이는 답변과 내부 실행 로그를 구분함
* 모든 중요한 결정에는 출처와 시간을 남김
