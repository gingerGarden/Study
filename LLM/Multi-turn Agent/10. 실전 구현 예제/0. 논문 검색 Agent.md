# 0. 논문 검색 Agent

이 문서는 Multi-turn Agent의 개념을 하나의 예제에 연결한 실전 설계 예시입니다.

예제 도메인은 기능성 원료 관련 논문을 검색하고, 결과를 주제별로 분류한 뒤, 보고서 형태로 정리하는 Agent입니다.

## 0.1. 예제 목표

사용자는 자연어로 논문 검색과 분석을 요청합니다.

Agent는 대화를 통해 부족한 조건을 확인하고, 검색 도구를 호출하며, 결과를 분류하고, 작업 상태를 유지해야 합니다.

```
사용자:
최근 5년간 기능성 원료 관련 논문을 찾아서 주제별로 분류해줘.

Agent:
검색 조건을 확인했습니다.
최근 5년 기준으로 기능성 원료 관련 논문을 검색하고, 결과를 주제별로 분류하겠습니다.
```

## 0.2. 요구사항

이 Agent가 처리해야 하는 요구사항은 다음과 같습니다.

| 구분 | 내용 |
| --- | --- |
| 검색 주제 | 기능성 원료 |
| 검색 기간 | 사용자가 지정하거나 기본값 사용 |
| 검색 결과 수 | 기본 100건 |
| 정렬 기준 | 관련도순 |
| 후처리 | 중복 제거, 주제 분류 |
| 출력 | 주제별 요약과 근거 논문 |
| 기억 | 사용자 선호와 프로젝트 결정사항 |

사용자가 한 번에 모든 조건을 말하지 않을 수 있으므로, Agent는 누락된 조건을 확인해야 합니다.

## 0.3. 전체 구조

```
사용자 입력
    ↓
Agent Controller
    ↓
최근 대화 조회
    ↓
Agent State 조회
    ↓
관련 Memory 검색
    ↓
Prompt 구성
    ↓
LLM 호출
    ↓
Tool Calling 또는 사용자 응답
    ↓
도구 결과 검증
    ↓
State·History·Memory 갱신
```

구현 관점에서는 다음 책임을 분리합니다.

| 구성 요소 | 책임 |
| --- | --- |
| Conversation History | 실제 대화 메시지 저장 |
| Agent State | 검색 조건과 진행 상태 저장 |
| Memory | 장기적으로 재사용할 선호와 결정 저장 |
| Tools | 논문 검색, 중복 제거, 분류, 보고서 생성 |
| Validator | 도구 입력값과 결과 검증 |
| Agent Controller | 한 턴의 실행 흐름 제어 |

## 0.4. Agent State Schema

논문 검색 Agent의 State는 다음처럼 정의할 수 있습니다.

```python
from pydantic import BaseModel, Field


class PaperSearchState(BaseModel):
    task: str = "paper_search"
    query: str | None = None
    start_year: int | None = None
    end_year: int | None = None
    result_limit: int = Field(default=100, ge=1, le=1000)
    sort_by: str = "relevance"
    classification_method: str | None = None
    current_step: str = "requirement_collection"
    completed_steps: list[str] = Field(default_factory=list)
    pending_steps: list[str] = Field(default_factory=list)
    last_tool_result_ref: str | None = None
```

예를 들어 사용자가 "최근 5년간 기능성 원료 논문을 찾아줘"라고 말하면 State는 다음처럼 갱신됩니다.

```json
{
  "task": "paper_search",
  "query": "기능성 원료",
  "start_year": 2021,
  "end_year": 2026,
  "result_limit": 100,
  "sort_by": "relevance",
  "classification_method": null,
  "current_step": "requirement_collection",
  "completed_steps": [
    "검색 주제 설정",
    "검색 기간 설정"
  ],
  "pending_steps": [
    "분류 방식 선택",
    "논문 검색"
  ],
  "last_tool_result_ref": null
}
```

State는 대화 원문을 저장하는 곳이 아니라, 실행에 필요한 확정 값을 저장하는 곳입니다.

## 0.5. Tool Schema

이 Agent는 다음 도구를 사용할 수 있습니다.

| 도구 | 역할 |
| --- | --- |
| search_papers | 논문 검색 |
| deduplicate_papers | 중복 논문 제거 |
| classify_papers | 논문 주제 분류 |
| summarize_papers | 논문 요약 |
| create_report | 보고서 생성 |

### search_papers

```python
from pydantic import BaseModel, Field, model_validator


class SearchPapersInput(BaseModel):
    query: str = Field(min_length=1)
    start_year: int = Field(ge=1900)
    end_year: int = Field(ge=1900)
    limit: int = Field(default=100, ge=1, le=1000)
    sort_by: str = "relevance"

    @model_validator(mode="after")
    def validate_year_range(self) -> "SearchPapersInput":
        if self.start_year > self.end_year:
            raise ValueError("start_year는 end_year보다 클 수 없습니다.")
        return self
```

LLM이 다음과 같은 도구 호출을 생성할 수 있습니다.

```json
{
  "tool": "search_papers",
  "arguments": {
    "query": "기능성 원료",
    "start_year": 2021,
    "end_year": 2026,
    "limit": 100,
    "sort_by": "relevance"
  }
}
```

도구 실행은 반드시 백엔드에서 검증 후 수행합니다.

## 0.6. Prompt 구성

한 턴에서 LLM에 전달하는 문맥은 다음 순서로 구성할 수 있습니다.

```
System Prompt
    +
Agent State
    +
관련 Memory
    +
최근 N턴 대화
    +
도구 실행 결과 요약
    +
현재 사용자 입력
```

예시는 다음과 같습니다.

```text
[System]
너는 논문 검색과 분석을 지원하는 Multi-turn Agent다.
확정된 조건은 Agent State를 기준으로 판단한다.
도구 호출 전에는 필요한 입력값이 모두 있는지 확인한다.

[Agent State]
query: 기능성 원료
start_year: 2021
end_year: 2026
result_limit: 100
classification_method: null
current_step: requirement_collection

[Memory]
- 사용자는 보고서 형식의 답변을 선호한다.
- 검색 결과에는 관련도 점수를 포함하기를 원한다.

[Recent Messages]
사용자: 기능성 원료 논문을 찾아줘.
Agent: 검색 기간을 지정해 주세요.
사용자: 최근 5년으로 해줘.

[Current User Input]
주제별로 분류해줘.
```

이 경우 Agent는 `classification_method`가 비어 있으므로, 기본 분류 방식을 사용할지 사용자에게 확인하거나, 시스템 정책에 정의된 기본값을 적용할 수 있습니다.

## 0.7. 한 턴 처리 흐름

사용자 입력:

```
최근 5년간 기능성 원료 관련 논문을 찾아서 주제별로 분류해줘.
```

처리 흐름:

```
1. 사용자 입력에서 query, start_year, end_year 추출
2. Agent State 갱신
3. 분류 방식 기본값 확인
4. search_papers 도구 호출
5. 검색 결과 검증
6. deduplicate_papers 도구 호출
7. classify_papers 도구 호출
8. State에 마지막 결과 참조 저장
9. 사용자에게 요약 응답
```

도구 결과 저장 예시:

```json
{
  "tool_call_id": "call_001",
  "tool": "search_papers",
  "status": "success",
  "summary": "기능성 원료 관련 논문 100건을 검색했습니다.",
  "result_ref": "artifact_paper_search_001"
}
```

State 갱신 예시:

```json
{
  "current_step": "classification_completed",
  "completed_steps": [
    "검색 조건 설정",
    "논문 검색",
    "중복 제거",
    "주제 분류"
  ],
  "pending_steps": [
    "보고서 생성"
  ],
  "last_tool_result_ref": "artifact_classification_001"
}
```

## 0.8. Memory 저장 예시

사용자가 다음과 같이 말할 수 있습니다.

```
앞으로 검색 결과에는 항상 관련도 점수를 포함해줘.
```

이 정보는 장기적으로 재사용할 사용자 선호이므로 Memory로 저장할 수 있습니다.

```json
{
  "content": "사용자는 논문 검색 결과에 관련도 점수가 포함되기를 원한다.",
  "memory_type": "preference",
  "scope": "user",
  "importance": 0.8,
  "source_message_id": "msg_105",
  "created_at": "2026-07-29T10:00:00+09:00",
  "status": "active"
}
```

반대로 다음과 같은 말은 Memory로 저장하지 않는 편이 좋습니다.

```
이번에는 그냥 대충 봐도 돼.
```

일회성 지시이므로 현재 State나 최근 대화에서만 처리하면 됩니다.

## 0.9. 실패 처리 예시

### 검색 결과가 없는 경우

```json
{
  "tool": "search_papers",
  "status": "success",
  "total_count": 0
}
```

Agent 응답:

```
조건에 맞는 논문을 찾지 못했습니다.
검색 기간을 넓히거나, 검색어를 "기능성 식품 원료" 또는 "bioactive ingredient"로 확장할 수 있습니다.
어떤 방식으로 진행할까요?
```

### 도구 입력값이 잘못된 경우

```json
{
  "tool": "search_papers",
  "arguments": {
    "start_year": 2026,
    "end_year": 2021
  },
  "validation_error": "start_year는 end_year보다 클 수 없습니다."
}
```

Agent는 도구를 실행하지 않고 사용자에게 확인해야 합니다.

```
검색 시작 연도가 종료 연도보다 큽니다.
2021년부터 2026년까지 검색하는 것으로 진행할까요?
```

### 분류 도구가 실패한 경우

```json
{
  "tool": "classify_papers",
  "status": "failed",
  "error_code": "MODEL_TIMEOUT",
  "retryable": true
}
```

처리 방식:

```
1. 최대 2회까지 재시도
2. 계속 실패하면 검색 결과 요약만 우선 제공
3. State에 classification_failed 기록
4. 사용자가 다시 시도할 수 있게 안내
```

## 0.10. 테스트 시나리오

Multi-turn Agent는 한 번의 입력과 출력만 테스트하면 부족합니다. 대화 흐름 전체를 테스트해야 합니다.

```json
{
  "name": "논문 검색 조건 수집 후 분류",
  "turns": [
    {
      "user": "논문을 찾아줘.",
      "expected_response_type": "clarification",
      "expected_missing_fields": ["query", "start_year", "end_year"]
    },
    {
      "user": "기능성 원료 관련으로 최근 5년.",
      "expected_state": {
        "query": "기능성 원료",
        "start_year": 2021,
        "end_year": 2026
      }
    },
    {
      "user": "주제별로 분류해줘.",
      "expected_tool_calls": [
        "search_papers",
        "deduplicate_papers",
        "classify_papers"
      ],
      "expected_state": {
        "current_step": "classification_completed"
      }
    }
  ]
}
```

추가로 테스트해야 할 시나리오는 다음과 같습니다.

* 사용자가 검색 기간을 중간에 변경함
* 검색 결과가 없음
* 도구 호출이 실패함
* 사용자가 이전 결정을 취소함
* Memory에 저장된 선호가 현재 요청에 반영됨
* 부작용이 있는 도구 실행 전 사용자 확인을 요구함

## 0.11. 최소 구현 의사코드

```python
def handle_turn(session_id: str, user_input: str) -> str:
    history = load_recent_messages(session_id, limit=10)
    state = load_agent_state(session_id)
    memories = search_memories(user_input, limit=5)

    extracted_state = extract_state_from_user_input(user_input, state)
    state = merge_state(state, extracted_state)

    prompt = build_prompt(
        history=history,
        state=state,
        memories=memories,
        user_input=user_input,
    )

    llm_response = call_llm(prompt)

    if llm_response.requires_clarification:
        save_message(session_id, "assistant", llm_response.content)
        save_agent_state(session_id, state)
        return llm_response.content

    if llm_response.tool_call:
        validated_input = validate_tool_input(llm_response.tool_call)
        tool_result = execute_tool(validated_input)
        save_tool_result(session_id, tool_result)
        state = update_state_with_tool_result(state, tool_result)
        save_agent_state(session_id, state)
        return continue_with_observation(session_id, tool_result)

    memories_to_write = extract_memories(user_input, llm_response.content)
    save_memories(memories_to_write)
    save_message(session_id, "assistant", llm_response.content)
    save_agent_state(session_id, state)

    return llm_response.content
```

이 의사코드는 실제 서비스 코드라기보다 책임 분리의 예시입니다. 핵심은 대화 이력, State, Memory, Tool, 검증 로직을 한 함수 안에 섞어 두지 않는 것입니다.

## 0.12. 확장 방향

이 예제를 실제 프로젝트로 확장하려면 다음 기능을 추가할 수 있습니다.

* 논문 검색 API 연동
* Vector DB 기반 Semantic Memory
* LangGraph 기반 Workflow 구현
* 장기 실행 Job과 진행률 표시
* 보고서 파일 생성
* 사용자 승인 단계
* 평가 데이터셋과 회귀 테스트
* 비용과 지연시간 모니터링

이 예제는 전체 문서 세트에서 설명한 개념을 하나의 흐름으로 묶는 기준 예제입니다. 실제 구현할 때는 먼저 이 구조를 작게 만든 뒤, 도구와 Memory, Workflow를 단계적으로 확장하는 것이 좋습니다.
