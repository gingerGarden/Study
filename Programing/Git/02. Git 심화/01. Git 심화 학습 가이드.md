## 전문가 기준

Git 전문가라고 부를 수 있으려면 다음을 설명하고 처리할 수 있어야 한다.

* 커밋이 내부적으로 어떤 객체로 구성되는지 설명할 수 있음
* 브랜치가 커밋을 가리키는 ref라는 사실을 이해함
* `merge`, `rebase`, `reset`, `revert`, `cherry-pick`의 차이를 상황별로 선택할 수 있음
* 충돌을 두려워하지 않고 원인을 확인한 뒤 해결할 수 있음
* `reflog`를 사용해 잃어버린 커밋을 복구할 수 있음
* 원격 추적 브랜치와 upstream 관계를 이해함
* 팀의 협업 전략에 맞는 브랜치 운영 방식을 선택할 수 있음
* secret 유출, 강제 push, 대형 파일 커밋 같은 운영 사고에 대응할 수 있음
* 터미널 출력 메시지를 보고 다음 확인 명령을 선택할 수 있음

## 학습 방식

문서를 읽을 때는 명령어를 외우기보다 다음 질문에 답하는 방식으로 접근한다.

* 이 명령은 어떤 공간을 바꾸는가?
* 커밋 이력이 바뀌는가?
* 원격 저장소와 협업자에게 영향이 있는가?
* 되돌릴 방법이 있는가?
* 실행 전 확인해야 할 명령은 무엇인가?
