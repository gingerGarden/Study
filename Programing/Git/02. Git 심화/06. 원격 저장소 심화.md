# 원격 저장소 심화

원격 저장소를 깊게 이해하려면 `fetch`, 원격 추적 브랜치, refspec, push 정책을 구분해야 한다.

## 1. fetch와 pull

`fetch`는 원격의 변경을 가져오지만 현재 브랜치에 합치지 않는다.

```bash
git fetch origin
```

`pull`은 가져온 뒤 현재 브랜치에 반영한다.

```bash
git pull origin main
```

기본적으로 `pull`은 fetch 후 merge에 가깝다. 설정에 따라 rebase 방식으로 동작하게 할 수도 있다.

```bash
git config --global pull.rebase false
git config --global pull.rebase true
```

## 2. 원격 추적 브랜치

`origin/main`은 원격 서버의 실시간 상태가 아니라 마지막 fetch 시점의 기록이다.

```bash
git fetch origin
git log --oneline main..origin/main
git log --oneline origin/main..main
```

* `main..origin/main`: 원격에만 있는 커밋
* `origin/main..main`: 로컬에만 있는 커밋

## 3. refspec

refspec은 어떤 ref를 어디로 가져오거나 보낼지 정의한다.

일반적인 fetch refspec:

```text
+refs/heads/*:refs/remotes/origin/*
```

의미:

* 원격의 모든 브랜치를 가져옴
* 로컬의 `refs/remotes/origin/*`에 저장함

## 4. prune

원격에서 삭제된 브랜치의 로컬 추적 브랜치를 정리한다.

```bash
git fetch --prune
```

항상 fetch 시 prune:

```bash
git config --global fetch.prune true
```

## 5. push 대상 확인

현재 브랜치의 upstream 확인:

```bash
git branch -vv
```

push 기본 정책 확인:

```bash
git config push.default
```

일반적으로 `simple`이 안전하다.

```bash
git config --global push.default simple
```

## 6. fork workflow

오픈소스 기여에서는 보통 원본 저장소와 내 fork 저장소를 함께 둔다.

```bash
git remote add origin git@github.com:myname/project.git
git remote add upstream git@github.com:original/project.git
```

원본 최신화:

```bash
git fetch upstream
git switch main
git merge upstream/main
git push origin main
```

## 7. shallow clone

최근 이력만 가져온다.

```bash
git clone --depth 1 https://github.com/username/repository.git
```

전체 이력이 필요해지면:

```bash
git fetch --unshallow
```
