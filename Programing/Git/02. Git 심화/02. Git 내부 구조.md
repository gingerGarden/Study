# Git 내부 구조

Git을 깊게 이해하려면 `.git` 디렉토리 안에서 무엇이 일어나는지 알아야 한다.

## 1. .git 디렉토리

`git init`을 실행하면 현재 디렉토리에 `.git` 디렉토리가 생긴다.

```bash
ls .git
```

주요 구성:

* `objects/`: Git 객체 저장소
* `refs/`: 브랜치와 태그 같은 참조 저장
* `HEAD`: 현재 위치를 가리키는 포인터
* `index`: 스테이징 영역
* `config`: 저장소별 설정
* `logs/`: reflog 기록

## 2. Git 객체

Git은 데이터를 객체로 저장한다. 핵심 객체는 네 가지이다.

* blob: 파일 내용
* tree: 디렉토리 구조와 파일 이름
* commit: tree, 부모 커밋, 작성자, 메시지
* tag: 특정 객체에 붙이는 이름

## 3. blob

blob은 파일 내용을 저장한다. 파일 이름은 blob에 저장되지 않는다.

```bash
git hash-object README.md
```

파일 이름은 tree 객체가 관리한다.

## 4. tree

tree는 디렉토리 구조를 나타낸다.

```bash
git cat-file -p HEAD^{tree}
```

tree는 파일 이름, 권한, blob 해시, 하위 tree 해시를 가진다.

## 5. commit

commit은 특정 시점의 프로젝트 상태와 이전 커밋을 연결한다.

```bash
git cat-file -p HEAD
```

commit 객체에는 보통 다음 정보가 있다.

* tree 해시
* 부모 커밋 해시
* 작성자
* 커밋 작성 시각
* 커밋 메시지

## 6. 커밋은 파일 차이가 아니라 스냅샷이다

Git은 커밋을 단순한 변경분 묶음으로만 저장하지 않는다. 각 커밋은 프로젝트 전체 상태를 가리키는 tree를 가진다.

다만 저장 공간을 효율적으로 쓰기 위해 내부적으로 중복 객체를 재사용하고, packfile로 압축한다.

## 7. index

index는 스테이징 영역이다.

```bash
git ls-files --stage
```

`git add`는 워킹 디렉토리의 변경을 index에 반영한다. `git commit`은 index를 기준으로 새 커밋을 만든다.

## 8. packfile

객체가 많아지면 Git은 loose object를 packfile로 압축한다.

```bash
git count-objects -v
git gc
```

일반 사용자가 직접 관리할 일은 많지 않지만, 대형 저장소 성능 문제를 볼 때 중요하다.
