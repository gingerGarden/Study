# 전문가 체크리스트

이 문서는 Git 전문가 수준에 도달했는지 점검하기 위한 목록이다.

## 1. 개념

다음을 설명할 수 있어야 한다.

* blob, tree, commit, tag 객체의 역할
* index와 워킹 디렉토리의 차이
* `HEAD`, 브랜치, ref의 관계
* 로컬 브랜치와 원격 추적 브랜치의 차이
* 커밋이 스냅샷이라는 의미

## 2. 기본 운용

다음을 막힘없이 수행할 수 있어야 한다.

* 새 저장소 생성
* 원격 저장소 clone
* 의미 있는 단위로 add/commit
* 브랜치 생성, 이동, 삭제
* merge와 충돌 해결
* push, fetch, pull
* stash 사용
* `.gitignore` 작성

## 3. 이력 관리

상황에 맞게 선택할 수 있어야 한다.

* `reset --soft`, `reset --mixed`, `reset --hard`
* `revert`
* `commit --amend`
* `rebase -i`
* `cherry-pick`
* `merge`
* `push --force-with-lease`

## 4. 복구

다음 상황을 복구할 수 있어야 한다.

* 실수로 브랜치를 삭제함
* `reset --hard` 후 커밋을 찾고 싶음
* detached HEAD에서 만든 커밋을 보존하고 싶음
* rebase 중 충돌이 복잡해져 중단하고 싶음
* merge 중 잘못 해결해서 다시 시작하고 싶음

핵심 명령:

```bash
git reflog
git fsck --lost-found
git branch rescue <커밋해시>
git merge --abort
git rebase --abort
```

## 5. 협업

다음을 판단할 수 있어야 한다.

* feature branch workflow가 적합한 상황
* Git Flow가 적합한 상황
* trunk-based development가 적합한 상황
* squash merge와 merge commit의 장단점
* PR 전에 확인해야 할 diff 범위
* 공유된 이력을 바꾸면 어떤 문제가 생기는지

## 6. 운영

다음을 알고 있어야 한다.

* secret을 커밋했을 때는 먼저 revoke/rotate해야 함
* protected branch가 왜 필요한지
* signed commit과 signed tag의 목적
* Git LFS가 필요한 상황
* shallow clone, sparse checkout, partial clone의 쓰임

## 7. 실전 질문

스스로 답해 본다.

* push가 거절되었을 때 어떤 순서로 확인할 것인가?
* pull 중 충돌이 나면 어떤 파일을 보고 어떻게 해결할 것인가?
* 이미 push한 커밋 메시지를 바꿔야 할 때 어떤 위험이 있는가?
* main에 잘못 들어간 커밋을 취소할 때 reset과 revert 중 무엇을 쓸 것인가?
* 사라진 커밋을 reflog에서 찾았다면 어떻게 보호할 것인가?
