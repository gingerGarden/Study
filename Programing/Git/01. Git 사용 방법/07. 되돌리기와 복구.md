# 되돌리기와 복구

되돌리기 명령은 영향을 주는 범위가 다르므로 구분해서 사용해야 한다.

## 1. 워킹 디렉토리 변경 취소

아직 스테이징하지 않은 파일 변경을 버린다.

```bash
git restore README.md
```

전체 파일의 미스테이징 변경을 버린다.

```bash
git restore .
```

주의: 이 명령은 파일 내용을 실제로 되돌리므로 저장하지 않은 수정이 사라진다.

## 2. 스테이징 취소

파일 수정 내용은 유지하고 스테이징만 취소한다.

```bash
git restore --staged README.md
```

전체 스테이징 취소:

```bash
git restore --staged .
```

## 3. 커밋을 되돌리는 새 커밋 만들기

이미 공유한 커밋을 취소할 때는 `revert`가 안전하다.

```bash
git revert <커밋 해시>
```

`revert`는 기존 커밋을 삭제하지 않고, 반대 변경을 담은 새 커밋을 만든다.

## 4. 커밋 자체를 이전으로 이동

로컬에서 아직 공유하지 않은 커밋을 정리할 때 `reset`을 사용할 수 있다.

마지막 커밋만 취소하고 변경 사항은 스테이징 상태로 유지:

```bash
git reset --soft HEAD~1
```

마지막 커밋만 취소하고 변경 사항은 워킹 디렉토리에 유지:

```bash
git reset --mixed HEAD~1
```

마지막 커밋과 변경 사항을 모두 버림:

```bash
git reset --hard HEAD~1
```

주의: `git reset --hard`는 작업 내용이 사라질 수 있다. 실행 전 `git status`와 `git log --oneline`을 반드시 확인한다.

## 5. 안전 기준

* 이미 공유한 커밋을 취소할 때는 `revert`를 우선 사용한다.
* 아직 공유하지 않은 로컬 커밋 정리에는 `reset`을 사용할 수 있다.
* 작업 내용을 버리는 명령 전에는 `git status`와 `git diff`를 확인한다.
