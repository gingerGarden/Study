# 실무 시나리오와 문제 해결

## 1. 새 프로젝트를 GitHub에 올리기

```bash
git init
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin https://github.com/username/repository.git
git push -u origin main
```

## 2. 기존 프로젝트에서 새 기능 작업하기

```bash
git switch main
git pull origin main
git switch -c feature-login
```

파일 수정 후:

```bash
git status
git add .
git commit -m "Add login feature"
git push -u origin feature-login
```

## 3. main에 작업 브랜치 병합하기

```bash
git switch main
git pull origin main
git merge feature-login
git push origin main
```

## 4. 원격 변경을 반영하고 계속 작업하기

```bash
git status
git pull origin main
```

작업 중인 변경 때문에 pull이 안 되면 먼저 커밋하거나 stash한다.

```bash
git stash
git pull origin main
git stash pop
```

## 5. 커밋하지 않은 수정 버리기

```bash
git status
git restore 파일명
```

전체 수정 버리기:

```bash
git restore .
```

## 6. 실수로 잘못 add한 파일 빼기

```bash
git restore --staged 파일명
```

## 7. 마지막 커밋 메시지 고치기

```bash
git commit --amend -m "Correct commit message"
```

## 8. push가 거절될 때

원격에 내가 아직 받지 않은 커밋이 있을 가능성이 높다.

```bash
git pull origin 현재브랜치명
git push origin 현재브랜치명
```

충돌이 발생하면 충돌을 해결한 뒤 다시 push한다.

## 9. pull 중 충돌이 났을 때

```bash
git status
```

충돌 파일을 수정한 뒤:

```bash
git add 충돌파일명
git commit
git push
```

pull 또는 merge를 취소하고 싶으면:

```bash
git merge --abort
```

## 10. 커밋할 게 없다고 나올 때

다음 중 하나일 수 있다.

* 파일을 저장하지 않았음
* 이미 커밋되어 있음
* `.gitignore`에 의해 제외됨
* 다른 디렉토리에서 명령을 실행 중임

확인 명령:

```bash
git status
git rev-parse --show-toplevel
```

## 11. 원격 저장소 연결이 이상할 때

```bash
git remote -v
```

주소를 바꾸려면:

```bash
git remote set-url origin 새_URL
```

## 12. 위험한 명령

강제 push:

```bash
git push -f origin main
```

사용하면 안 되는 상황:

* 협업자가 함께 쓰는 `main`, `develop` 브랜치
* 원격에 내가 아직 받지 않은 커밋이 있을 수 있는 상황
* push 거절 원인을 확인하지 않은 상황

더 안전한 방식:

```bash
git push --force-with-lease
```

hard reset:

```bash
git reset --hard HEAD~1
```

사용하면 안 되는 상황:

* 아직 커밋하지 않은 중요한 변경이 있는 상황
* 현재 브랜치와 커밋 위치를 확인하지 않은 상황
* 복구할 커밋 해시나 백업 브랜치가 없는 상황

이 명령들은 이력을 덮어쓰거나 작업 내용을 버릴 수 있다. 실행 전 다음을 확인한다.

```bash
git status
git log --oneline
```

불안하면 먼저 백업 브랜치를 만든다.

```bash
git branch backup-before-dangerous-command
```
