# rebase와 cherry-pick

## 1. rebase

`rebase`는 현재 브랜치의 커밋들을 다른 기준 커밋 위로 다시 쌓는 작업이다.

예를 들어 `feature-login` 브랜치에서 작업하는 동안 `main`이 업데이트되었다면 다음처럼 내 작업 브랜치를 최신 `main` 위로 올릴 수 있다.

```bash
git switch feature-login
git fetch origin
git rebase origin/main
```

`merge`와 비교하면 다음 차이가 있다.

* `merge`: 두 브랜치의 이력을 합치고 병합 커밋을 만들 수 있음
* `rebase`: 내 커밋의 기반을 옮겨 이력을 직선처럼 정리함

주의: 이미 원격에 push해서 다른 사람이 받을 수 있는 커밋은 함부로 rebase하지 않는다. 커밋 해시가 바뀐다.

## 2. rebase 충돌 해결

rebase 중 충돌이 발생하면 파일을 수정하고 다음 명령을 실행한다.

```bash
git add 충돌파일명
git rebase --continue
```

rebase를 중단하려면:

```bash
git rebase --abort
```

## 3. cherry-pick

`cherry-pick`은 다른 브랜치의 특정 커밋 하나만 현재 브랜치로 가져오는 명령이다.

```bash
git cherry-pick <커밋 해시>
```

예시:

```bash
git switch main
git cherry-pick a1b2c3d
```

사용 상황:

* 다른 브랜치의 버그 수정 커밋 하나만 가져오고 싶을 때
* 전체 브랜치를 merge하지 않고 필요한 커밋만 적용하고 싶을 때

주의: 같은 변경을 나중에 merge할 때 중복 이력이나 충돌이 생길 수 있으므로 필요한 경우에만 사용한다.
