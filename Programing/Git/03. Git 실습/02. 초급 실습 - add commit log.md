# 초급 실습 - add commit log

목표:

* Git 저장소를 만들 수 있다.
* 파일 수정, 스테이징, 커밋을 할 수 있다.
* `status`, `diff`, `log` 출력 의미를 읽을 수 있다.

## 1. 저장소 만들기

```bash
mkdir git-basic-practice
cd git-basic-practice
git init
```

## 2. 파일 만들고 상태 확인

```bash
printf "Git practice\n" > README.md
git status
```

예상 출력:

```text
Untracked files:
  README.md

nothing added to commit but untracked files present
```

해석:

* `README.md`는 아직 Git이 추적하지 않는 파일이다.
* 커밋하려면 먼저 `git add`가 필요하다.

## 3. 스테이징

```bash
git add README.md
git status
```

예상 출력:

```text
Changes to be committed:
  new file:   README.md
```

해석:

* 다음 커밋에 `README.md`가 포함될 준비가 되었다.

## 4. 커밋

```bash
git commit -m "Add README"
git log --oneline
```

예상 출력:

```text
a1b2c3d Add README
```

해석:

* 커밋 해시와 메시지가 보인다.
* 이제 이 시점으로 되돌아갈 기준점이 생겼다.

## 5. 변경 비교

```bash
printf "\nSecond line\n" >> README.md
git diff
```

예상 출력 일부:

```diff
+Second line
```

해석:

* `+`로 시작하는 줄은 새로 추가된 내용이다.

## 6. 점검 문제

다음 질문에 답한다.

* `git add` 전과 후의 `git status`는 어떻게 다른가?
* `git diff`와 `git diff --staged`는 언제 다른 결과를 보여 주는가?
* 커밋 메시지가 `update`이면 왜 나쁜가?
