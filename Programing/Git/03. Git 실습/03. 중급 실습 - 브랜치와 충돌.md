# 중급 실습 - 브랜치와 충돌

목표:

* 브랜치를 만들고 병합할 수 있다.
* 충돌을 직접 재현하고 해결할 수 있다.
* 충돌 표시의 의미를 해석할 수 있다.

## 1. 준비

```bash
mkdir git-conflict-practice
cd git-conflict-practice
git init
printf "title: Git\n" > note.txt
git add note.txt
git commit -m "Add note"
```

## 2. feature 브랜치에서 수정

```bash
git switch -c feature-title
printf "title: Git Guide\n" > note.txt
git add note.txt
git commit -m "Update title in feature"
```

## 3. main에서 같은 줄 수정

```bash
git switch main
printf "title: Git Manual\n" > note.txt
git add note.txt
git commit -m "Update title in main"
```

## 4. 병합해서 충돌 만들기

```bash
git merge feature-title
```

예상 출력:

```text
CONFLICT (content): Merge conflict in note.txt
Automatic merge failed; fix conflicts and then commit the result.
```

해석:

* `note.txt` 같은 줄을 두 브랜치가 다르게 수정했다.
* Git이 자동으로 선택할 수 없어 사용자의 판단이 필요하다.

## 5. 충돌 파일 확인

```bash
cat note.txt
```

예상 내용:

```text
<<<<<<< HEAD
title: Git Manual
=======
title: Git Guide
>>>>>>> feature-title
```

해석:

* `HEAD` 아래는 현재 브랜치인 `main`의 내용이다.
* `=======` 아래는 병합하려는 `feature-title`의 내용이다.

## 6. 충돌 해결

원하는 최종 내용으로 파일을 정리한다.

```bash
printf "title: Git Expert Guide\n" > note.txt
git add note.txt
git commit -m "Merge feature title"
```

## 7. 점검 문제

* `git merge --abort`는 언제 사용하는가?
* 충돌 표시를 지우지 않고 커밋하면 어떤 문제가 생기는가?
* 현재 브랜치 내용만 선택하려면 어떤 명령을 쓸 수 있는가?
