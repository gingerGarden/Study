# 종합 문제

이 문서는 상황을 보고 어떤 명령을 선택해야 하는지 훈련하기 위한 문제 모음이다.

## 1. 상황 판단 문제

### 문제 1

파일을 수정했는데 커밋에는 포함하고 싶지 않다. 수정 내용도 버리고 싶다.

사용할 명령:

```bash
git restore 파일명
```

### 문제 2

실수로 `git add .`를 했지만 파일 수정 내용은 유지하고 싶다.

사용할 명령:

```bash
git restore --staged .
```

### 문제 3

이미 원격에 올라간 커밋 하나를 취소해야 한다.

사용할 명령:

```bash
git revert 커밋해시
```

이유:

* 공유된 이력을 삭제하지 않고 취소 커밋을 추가하기 때문이다.

### 문제 4

아직 push하지 않은 최근 커밋 3개를 메시지까지 정리하고 싶다.

사용할 명령:

```bash
git rebase -i HEAD~3
```

### 문제 5

`reset --hard` 후 사라진 커밋을 찾고 싶다.

사용할 명령:

```bash
git reflog
```

## 2. 출력 해석 문제

### 출력 1

```text
Changes not staged for commit:
  modified: README.md
```

해석:

* `README.md`가 수정됐지만 아직 스테이징되지 않았다.
* 커밋에 포함하려면 `git add README.md`가 필요하다.

### 출력 2

```text
CONFLICT (content): Merge conflict in app.txt
Automatic merge failed; fix conflicts and then commit the result.
```

해석:

* `app.txt`에서 내용 충돌이 발생했다.
* 파일을 직접 수정하고 `git add`, `git commit`을 해야 한다.

### 출력 3

```text
You are in 'detached HEAD' state.
```

해석:

* 현재 브랜치가 아니라 특정 커밋을 직접 보고 있다.
* 여기서 만든 커밋은 브랜치를 만들어 보호하는 것이 좋다.

```bash
git switch -c rescue-branch
```

## 3. 위험 명령 판단

### 문제 1

협업 중인 `main` 브랜치에서 `git push -f origin main`을 실행하려 한다.

판단:

* 실행하지 않는다.
* 원격 이력을 덮어써서 협업자의 커밋을 잃게 만들 수 있다.

대안:

```bash
git pull origin main
git revert 문제커밋해시
git push origin main
```

### 문제 2

작업 중인 파일이 있는데 `git reset --hard HEAD~1`을 실행하려 한다.

판단:

* 먼저 상태와 변경 내용을 확인한다.

```bash
git status
git diff
git branch backup-before-reset
```

그 후 정말 버려도 되는 변경인지 판단한다.

### 문제 3

개인 브랜치에서 push한 커밋 메시지를 고쳐야 한다.

판단:

* 다른 사람이 사용하지 않는 브랜치라면 가능하다.
* 그래도 강제 push는 `--force-with-lease`를 사용한다.

```bash
git commit --amend -m "Correct message"
git push --force-with-lease
```
