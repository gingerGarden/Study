# 고급 실습 - rebase와 이력 정리

목표:

* interactive rebase로 커밋 메시지를 고치고 커밋을 합칠 수 있다.
* rebase 중 충돌이 날 때 해결 흐름을 이해한다.
* 공유된 커밋을 rebase하면 위험한 이유를 설명할 수 있다.

## 1. 준비

```bash
mkdir git-rebase-practice
cd git-rebase-practice
git init
printf "base\n" > app.txt
git add app.txt
git commit -m "Add base"
printf "login\n" >> app.txt
git add app.txt
git commit -m "wip"
printf "validation\n" >> app.txt
git add app.txt
git commit -m "fix"
git log --oneline
```

## 2. interactive rebase 실행

```bash
git rebase -i HEAD~2
```

편집기가 열리면 다음처럼 바꾼다.

```text
reword <첫번째해시> wip
fixup <두번째해시> fix
```

첫 번째 커밋 메시지를 다음처럼 수정한다.

```text
Add login validation
```

결과 확인:

```bash
git log --oneline
```

해석:

* 두 커밋이 하나로 정리된다.
* 커밋 해시는 바뀐다.

## 3. rebase 중단

rebase 중 실수했거나 상태가 헷갈리면 중단할 수 있다.

```bash
git rebase --abort
```

## 4. 공유된 커밋에서의 위험

이미 원격에 push한 커밋을 rebase하면 커밋 해시가 바뀐다. 다른 사람이 기존 커밋을 기준으로 작업 중이면 이력이 꼬일 수 있다.

강제 push가 꼭 필요할 때는 다음을 사용한다.

```bash
git push --force-with-lease
```

`--force-with-lease`는 내가 모르는 원격 변경이 있으면 push를 막는다.
