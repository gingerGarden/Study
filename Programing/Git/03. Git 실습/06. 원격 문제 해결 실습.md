# 원격 문제 해결 실습

목표:

* push 거절 메시지를 해석할 수 있다.
* `fetch`, `pull`, 원격 추적 브랜치의 차이를 이해한다.
* 원격 브랜치 정리와 upstream 설정을 할 수 있다.

## 1. push가 거절되는 상황

대표 메시지:

```text
! [rejected] main -> main (fetch first)
error: failed to push some refs
hint: Updates were rejected because the remote contains work that you do not have locally.
```

해석:

* 원격에 내가 아직 받지 않은 커밋이 있다.
* 먼저 원격 변경을 가져와야 한다.

해결 흐름:

```bash
git status
git fetch origin
git log --oneline --graph --decorate --all
git pull origin main
git push origin main
```

## 2. ahead와 behind 해석

```bash
git status
```

예상 출력:

```text
Your branch is ahead of 'origin/main' by 1 commit.
```

해석:

* 로컬에만 있는 커밋이 1개 있다.
* push하면 원격에 반영된다.

```text
Your branch is behind 'origin/main' by 1 commit.
```

해석:

* 원격에만 있는 커밋이 1개 있다.
* pull 또는 fetch 후 merge/rebase가 필요하다.

## 3. upstream 설정

현재 브랜치의 upstream 확인:

```bash
git branch -vv
```

처음 push하면서 설정:

```bash
git push -u origin feature-login
```

이미 있는 브랜치에 upstream 설정:

```bash
git branch --set-upstream-to=origin/feature-login feature-login
```

## 4. 삭제된 원격 브랜치 정리

원격에서 삭제된 브랜치의 추적 정보를 정리한다.

```bash
git fetch --prune
```

항상 자동 정리:

```bash
git config --global fetch.prune true
```
