## 1. HTTP 요청 구성
API를 호출할 때 클라이언트는 서버에게 HTTP 요청을 보낸다. 요청은 보통 URL, HTTP 메서드, 헤더, 파라미터, 본문으로 구성된다.

<br>

1.1. URL
* API가 제공하는 기능에 접근하기 위한 주소.
* 예시: `https://api.example.com/users/123`
* URL은 보통 서버 주소, 경로, 쿼리 문자열로 나뉜다.

```text
https://api.example.com/users?role=admin&page=1
```

| 구분 | 예시 | 의미 |
|----|----|----|
| 서버 주소 | `https://api.example.com` | API 서버의 기본 주소 |
| 경로 | `/users` | 접근하려는 자원 |
| 쿼리 문자열 | `?role=admin&page=1` | 추가 검색 조건 |

<br>

1.2. HTTP 메서드
HTTP 메서드는 서버에게 어떤 작업을 요청하는지 나타낸다.

| 메서드 | 목적 | 예시 |
|----|----|----|
| `GET` | 데이터 조회 | 사용자 목록 조회 |
| `POST` | 데이터 생성 | 새 사용자 등록 |
| `PUT` | 데이터 전체 수정 | 사용자 정보 전체 교체 |
| `PATCH` | 데이터 일부 수정 | 사용자 이름만 수정 |
| `DELETE` | 데이터 삭제 | 사용자 삭제 |

<br>

1.3. Header
Header는 요청에 대한 부가 정보를 담는 영역이다.

```http
Content-Type: application/json
Authorization: Bearer access_token
Accept: application/json
```

* `Content-Type`: 요청 본문의 데이터 형식
* `Authorization`: 인증 정보
* `Accept`: 클라이언트가 받고 싶은 응답 형식

<br>

1.4. Query Parameter
Query Parameter는 URL 뒤에 붙는 검색 조건이다.

```text
GET /books?query=javascript&page=1&size=10
```

* `query=javascript`: 검색어
* `page=1`: 페이지 번호
* `size=10`: 한 페이지에 받을 데이터 개수

주로 조회 조건, 검색어, 정렬 방식, 페이지네이션에 사용된다.

<br>

1.5. Path Parameter
Path Parameter는 URL 경로 안에 포함되는 값이다.

```text
GET /users/123
```

위 요청에서 `123`은 특정 사용자의 ID를 의미한다.

<br>

1.6. Body
Body는 서버로 보낼 실제 데이터를 담는 영역이다. 주로 `POST`, `PUT`, `PATCH` 요청에서 사용한다.

```json
{
  "name": "Kim",
  "email": "kim@example.com"
}
```

`GET` 요청은 보통 Body를 사용하지 않고, 필요한 조건은 Query Parameter로 전달한다.

<br>
<br>

## 2. HTTP 상태 코드
HTTP 상태 코드는 서버가 요청을 처리한 결과를 숫자로 알려주는 값이다.

<br>

2.1. 2xx 성공
| 상태 코드 | 이름 | 의미 |
|----|----|----|
| `200` | OK | 요청 성공 |
| `201` | Created | 생성 성공 |
| `204` | No Content | 성공했지만 응답 본문 없음 |

<br>

2.2. 4xx 클라이언트 오류
| 상태 코드 | 이름 | 의미 |
|----|----|----|
| `400` | Bad Request | 요청 형식이 잘못됨 |
| `401` | Unauthorized | 인증이 필요하거나 인증 실패 |
| `403` | Forbidden | 인증은 되었지만 권한이 없음 |
| `404` | Not Found | 요청한 자원이 없음 |
| `409` | Conflict | 현재 서버 상태와 요청이 충돌함 |
| `429` | Too Many Requests | 너무 많은 요청을 보냄 |

<br>

2.3. 5xx 서버 오류
| 상태 코드 | 이름 | 의미 |
|----|----|----|
| `500` | Internal Server Error | 서버 내부 오류 |
| `502` | Bad Gateway | 중간 서버가 잘못된 응답을 받음 |
| `503` | Service Unavailable | 서버가 일시적으로 요청을 처리할 수 없음 |

<br>

2.4. 상태 코드 해석 예시
```text
GET /users/123
```

* `200 OK`: 사용자 정보를 정상적으로 받음.
* `404 Not Found`: ID가 123인 사용자가 없음.
* `401 Unauthorized`: 로그인이나 토큰이 필요함.
* `500 Internal Server Error`: 서버 처리 중 문제가 발생함.
