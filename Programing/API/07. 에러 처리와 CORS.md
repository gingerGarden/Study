## 1. API 에러 처리
API 요청은 항상 성공하지 않는다. 네트워크 문제, 잘못된 요청, 인증 실패, 서버 오류 등 다양한 이유로 실패할 수 있다.

<br>

## 2. fetch의 기본 특징
`fetch`는 서버가 `404`나 `500` 상태 코드를 응답해도 자동으로 에러를 던지지 않는다. 네트워크 자체가 실패한 경우에만 `catch`로 이동한다.

따라서 `response.ok`를 확인해야 한다.

```javascript
async function getUser(id) {
  const response = await fetch(`https://api.example.com/users/${id}`);

  if (!response.ok) {
    throw new Error(`API 요청 실패: ${response.status}`);
  }

  const user = await response.json();
  return user;
}
```

* `response.ok`: 상태 코드가 `200` 이상 `299` 이하이면 `true`
* `response.status`: HTTP 상태 코드
* `response.statusText`: 상태 코드 설명

<br>

## 3. try/catch 사용
```javascript
async function loadUser(id) {
  try {
    const response = await fetch(`https://api.example.com/users/${id}`);

    if (!response.ok) {
      throw new Error(`상태 코드: ${response.status}`);
    }

    const user = await response.json();
    console.log(user);
  } catch (error) {
    console.error("사용자 정보를 불러오지 못했습니다.", error);
  }
}
```

`try` 영역에는 실패할 수 있는 코드를 작성하고, `catch` 영역에는 실패했을 때의 처리를 작성한다.

<br>

## 4. 상태 코드별 처리 예시
```javascript
async function request(url) {
  const response = await fetch(url);

  if (response.status === 401) {
    throw new Error("로그인이 필요합니다.");
  }

  if (response.status === 403) {
    throw new Error("접근 권한이 없습니다.");
  }

  if (response.status === 404) {
    throw new Error("요청한 데이터를 찾을 수 없습니다.");
  }

  if (!response.ok) {
    throw new Error("요청 처리 중 문제가 발생했습니다.");
  }

  return response.json();
}
```

상태 코드에 따라 사용자에게 보여줄 메시지나 후속 처리를 다르게 만들 수 있다.

<br>

## 5. CORS
CORS(Cross-Origin Resource Sharing)는 브라우저가 서로 다른 출처 간 요청을 제한하는 보안 정책이다. 서버와 서버 사이의 요청에는 브라우저의 CORS 정책이 적용되지 않는다.

출처는 프로토콜, 도메인, 포트의 조합이다.

```text
http://localhost:3000
https://example.com
https://api.example.com
```

위 주소들은 서로 다른 출처로 볼 수 있다.

<br>

## 6. CORS가 발생하는 상황
프론트엔드가 `http://localhost:3000`에서 실행되고, API 서버가 `https://api.example.com`에 있을 때 브라우저는 다른 출처로 요청한다고 판단한다.

이때 API 서버가 허용 응답 헤더를 보내지 않으면 브라우저가 응답을 차단한다.

```http
Access-Control-Allow-Origin: http://localhost:3000
```

<br>

## 7. CORS 해결 방식
* API 서버에서 허용할 출처를 설정한다.
* 개발 환경에서는 프록시 서버를 사용해 같은 출처처럼 요청한다.
* 인증 쿠키를 사용할 경우 `Access-Control-Allow-Credentials` 설정도 확인한다.
* 보안상 `Access-Control-Allow-Origin: *`와 인증 쿠키를 함께 사용할 수 없다.

CORS는 프론트엔드 코드만으로 완전히 해결할 수 없는 경우가 많다. 최종적으로는 API 서버가 어떤 출처의 요청을 허용할지 정해야 한다.

<br>
