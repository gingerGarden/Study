## 1. API 인증
API 인증은 요청을 보낸 사용자가 누구인지 확인하는 과정이다. 인증이 필요한 API는 요청에 인증 정보를 함께 보내야 한다.

<br>

## 2. API Key
API Key는 API 제공자가 발급하는 고유한 문자열이다. 클라이언트는 요청할 때 API Key를 함께 보내 자신이 허용된 사용자임을 나타낸다.

```http
GET /books?query=javascript
Authorization: KakaoAK api_key
```

또는 서비스에 따라 Query Parameter로 보낼 수도 있다.

```text
GET /weather?city=seoul&apikey=api_key
```

* 장점: 구현이 단순함.
* 단점: 키가 노출되면 다른 사람이 API를 사용할 수 있음.
* 주의: 프론트엔드 코드에 중요한 API Key를 그대로 넣으면 노출될 수 있음.

<br>

## 3. Bearer Token
Bearer Token은 로그인이나 인증 과정을 거친 뒤 발급받는 토큰이다. API 요청 시 `Authorization` 헤더에 넣어 보낸다.

```http
Authorization: Bearer access_token
```

예시:

```javascript
fetch("https://api.example.com/me", {
  headers: {
    Authorization: "Bearer access_token"
  }
});
```

* `access_token`: API 접근에 사용하는 토큰
* `refresh_token`: access token을 다시 발급받기 위한 토큰

Bearer Token은 보통 로그인 기반 서비스에서 많이 사용한다.

<br>

## 4. OAuth 기초
OAuth는 사용자의 비밀번호를 직접 공유하지 않고, 외부 서비스의 권한을 위임받는 인증 방식이다.

예를 들어 어떤 앱이 구글 계정의 프로필 정보를 가져오고 싶을 때, 사용자는 구글 로그인 화면에서 권한을 허용한다. 앱은 사용자의 구글 비밀번호를 알지 못하고, 대신 토큰을 받아 API를 호출한다.

<br>

OAuth의 기본 흐름:
1. 사용자가 외부 서비스 로그인 화면으로 이동
2. 사용자가 권한 허용
3. 외부 서비스가 인증 코드를 앱에 전달
4. 앱이 인증 코드를 토큰으로 교환
5. 앱이 토큰으로 API 호출

<br>

## 5. 인증 정보 관리 주의사항
* API Key와 토큰은 공개 저장소에 올리지 않는다.
* 브라우저에서 노출되면 안 되는 키는 백엔드에서 관리한다.
* HTTPS를 사용해 인증 정보가 평문으로 전송되지 않게 한다.
* 토큰에는 만료 시간을 두고, 필요할 때 재발급한다.
* 권한은 필요한 범위만 부여한다.
