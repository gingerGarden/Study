## 1. API 테스트
API 테스트는 요청을 보내고 응답이 기대한 규칙을 만족하는지 확인하는 과정이다.

테스트 대상:
* 상태 코드
* 응답 JSON 구조
* 필수 필드
* 인증과 권한
* 에러 응답
* 성능과 제한 정책

<br>

## 2. curl
`curl`은 터미널에서 HTTP 요청을 보내는 도구이다.

GET 요청:

```bash
curl https://api.example.com/users
```

POST 요청:

```bash
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"Kim","email":"kim@example.com"}'
```

인증 요청:

```bash
curl https://api.example.com/me \
  -H "Authorization: Bearer access_token"
```

<br>

## 3. Postman
Postman은 API 요청을 저장하고 실행하며 팀과 공유할 수 있는 도구이다.

활용:
* API 요청 모음 관리
* 환경 변수 관리
* 인증 헤더 자동 설정
* 응답 확인
* 간단한 테스트 스크립트 작성

Postman은 API를 처음 탐색하거나 수동 테스트할 때 유용하다.

<br>

## 4. Integration Test
Integration Test는 실제 API 서버 또는 테스트 서버를 실행한 뒤 HTTP 요청을 보내 전체 흐름을 검증한다.

검증 예시:
* 사용자 생성 API 호출
* 생성된 사용자 조회
* 응답 상태 코드와 JSON 필드 확인
* 테스트 데이터 정리

Integration Test는 단위 테스트보다 느리지만 실제 동작을 더 잘 검증한다.

<br>

## 5. Contract Testing
Contract Testing은 API 제공자와 소비자 사이의 계약이 지켜지는지 검증하는 테스트이다.

예를 들어 프론트엔드가 다음 응답을 기대한다고 가정한다.

```json
{
  "id": 1,
  "name": "Kim"
}
```

백엔드가 `name` 필드를 제거하거나 타입을 바꾸면 클라이언트가 깨질 수 있다. Contract Testing은 이런 변경을 미리 발견하는 데 도움을 준다.

<br>

## 6. Mock Server
Mock Server는 실제 API 서버가 없어도 정해진 응답을 반환하는 가짜 서버이다.

활용:
* 프론트엔드 개발을 백엔드 개발과 병렬 진행
* 외부 API 장애와 무관하게 테스트
* 특정 에러 응답 상황 재현

<br>

## 7. 테스트 체크리스트
* 성공 응답과 실패 응답을 모두 테스트했는가?
* 인증 실패와 권한 부족을 구분해 테스트했는가?
* 필수 파라미터 누락을 테스트했는가?
* 응답 JSON 구조를 검증하는가?
* API 문서와 실제 응답이 일치하는지 확인하는가?
* 외부 API는 mock으로 대체할 수 있는가?

<br>

## 8. 최소 테스트 시나리오 예시
사용자 API를 만든다면 최소한 다음 흐름은 검증하는 것이 좋다.

1. 사용자 생성 요청이 `201 Created`를 반환하는지 확인
2. 생성된 사용자를 `GET /users/{id}`로 조회할 수 있는지 확인
3. 필수 값이 빠진 생성 요청이 `400 Bad Request`를 반환하는지 확인
4. 없는 사용자를 조회하면 `404 Not Found`를 반환하는지 확인
5. 인증이 필요한 API를 토큰 없이 호출하면 `401 Unauthorized`를 반환하는지 확인
6. 권한이 부족한 사용자가 관리자 API를 호출하면 `403 Forbidden`을 반환하는지 확인
