## 1. 실무 API 응답 설계
실무 API는 성공 응답뿐 아니라 실패 응답, 목록 응답, 페이지네이션, 에러 코드까지 일관되게 설계해야 한다.

<br>

## 2. 성공 응답
단일 자원 응답:

```json
{
  "id": 1,
  "name": "Kim",
  "email": "kim@example.com"
}
```

목록 응답:

```json
{
  "items": [
    {
      "id": 1,
      "name": "Kim"
    },
    {
      "id": 2,
      "name": "Lee"
    }
  ],
  "page": {
    "page": 1,
    "size": 20,
    "totalItems": 42,
    "totalPages": 3
  }
}
```

목록 응답은 배열만 반환하는 것보다 페이지 정보와 함께 감싸는 편이 확장에 유리하다.

<br>

## 3. 에러 응답 표준화
에러 응답도 일정한 형식을 사용해야 클라이언트가 처리하기 쉽다.

```json
{
  "error": {
    "code": "USER_NOT_FOUND",
    "message": "사용자를 찾을 수 없습니다.",
    "details": {
      "userId": 123
    }
  }
}
```

필드 검증 실패 예시:

```json
{
  "error": {
    "code": "VALIDATION_FAILED",
    "message": "요청 값이 올바르지 않습니다.",
    "fields": [
      {
        "name": "email",
        "reason": "이메일 형식이 아닙니다."
      }
    ]
  }
}
```

<br>

## 4. 에러 코드 설계
HTTP 상태 코드는 오류의 큰 분류를 나타내고, 서비스 에러 코드는 구체적인 원인을 나타낸다.

| HTTP 상태 코드 | 서비스 에러 코드 | 의미 |
|----|----|----|
| `400` | `VALIDATION_FAILED` | 요청 값 검증 실패 |
| `401` | `AUTH_REQUIRED` | 인증 필요 |
| `403` | `PERMISSION_DENIED` | 권한 없음 |
| `404` | `USER_NOT_FOUND` | 사용자 없음 |
| `409` | `EMAIL_ALREADY_EXISTS` | 이메일 중복 |
| `429` | `RATE_LIMIT_EXCEEDED` | 요청 제한 초과 |
| `500` | `INTERNAL_ERROR` | 서버 내부 오류 |

<br>

## 5. 간단한 백엔드 구현 예시
Node.js와 Express를 사용한 예시이다.

```javascript
const express = require("express");

const app = express();
app.use(express.json());

const users = [
  { id: 1, name: "Kim", email: "kim@example.com" }
];

app.get("/users/:id", (req, res) => {
  const id = Number(req.params.id);
  const user = users.find((item) => item.id === id);

  if (!user) {
    return res.status(404).json({
      error: {
        code: "USER_NOT_FOUND",
        message: "사용자를 찾을 수 없습니다.",
        details: { userId: id }
      }
    });
  }

  return res.status(200).json(user);
});

app.post("/users", (req, res) => {
  const { name, email } = req.body;

  if (!name || !email) {
    return res.status(400).json({
      error: {
        code: "VALIDATION_FAILED",
        message: "name과 email은 필수입니다."
      }
    });
  }

  const user = {
    id: users.length + 1,
    name,
    email
  };

  users.push(user);
  return res.status(201).json(user);
});

app.listen(3000, () => {
  console.log("API server listening on port 3000");
});
```

## 6. 프론트엔드 연동 예시
```javascript
async function loadUser(id) {
  const response = await fetch(`http://localhost:3000/users/${id}`);
  const data = await response.json();

  if (!response.ok) {
    alert(data.error.message);
    return;
  }

  document.querySelector("#name").textContent = data.name;
  document.querySelector("#email").textContent = data.email;
}
```

프론트엔드는 HTTP 상태 코드와 에러 응답 구조를 함께 확인해야 한다.

## 8. 미니 프로젝트 과제
아래 요구사항을 만족하는 간단한 사용자 API를 직접 만들어본다.

기능:
* `GET /users`: 사용자 목록 조회
* `GET /users/{id}`: 사용자 상세 조회
* `POST /users`: 사용자 생성
* `PATCH /users/{id}`: 사용자 일부 수정
* `DELETE /users/{id}`: 사용자 삭제

필수 조건:
* 요청과 응답은 JSON 형식을 사용한다.
* 성공과 실패에 맞는 HTTP 상태 코드를 반환한다.
* 에러 응답은 `error.code`, `error.message` 구조를 사용한다.
* 목록 조회는 `page`, `size` Query Parameter를 받는다.
* OpenAPI 문서를 작성한다.
* `curl` 또는 Postman으로 성공/실패 케이스를 테스트한다.

완료 기준:
* 사용자를 생성한 뒤 조회할 수 있다.
* 없는 사용자를 조회하면 `404`가 반환된다.
* 필수 값이 빠지면 `400`이 반환된다.
* 문서의 요청/응답 예시와 실제 API 응답이 일치한다.
